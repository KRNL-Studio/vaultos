# Changelog

## 0.3.0-preview.1 (unreleased)

VaultOS is now Rust throughout. Electron, Chromium, Node.js and every npm runtime dependency are gone; Node.js is needed only to run the build and test scripts.

- Desktop: a Tauri v2 app around the same pages, running in the system web view (WKWebView on macOS, WebKitGTK on Linux). Its calls are two Rust commands, each accepted only from its own window at its own page; links never navigate a window and new windows are refused.
- Vault format v4 for everyone: Argon2id, an optional Secret Key kept in the Keychain or Secret Service, one key per project, item metadata and secrets sealed separately with XChaCha20-Poly1305, a whole-file MAC and a signed, hash-chained audit log. A vault from 0.2 opens only to be upgraded, when you choose **Upgrade this vault** (or run `vaultos upgrade`); the upgrade is one-way and keeps the v3 file as a backup.
- Agents: the app serves the agent API itself on a private Unix socket that accepts only your user, instead of a localhost HTTP port. The MCP bridge (`vaultos-mcp`), the agent shell client (`vaultos-agent`), the human CLI (`vaultos`) and the headless owner (`vaultosd`) ship inside the app; MCP configurations point at `VaultOS.app/Contents/Helpers/vaultos-mcp` and need no Node.js or source checkout. The tool names and schemas are unchanged.
- Background access: `VaultOS --service` replaces `backend.cjs --service`. `scripts/install-service-macos.sh` and `scripts/install-linux.sh --enable-service` install it. It waits while a window owns the vault, takes over when the window closes, never serves after a Lock or hard automatic lock until a human unlocks, and exits 0 for conditions a restart cannot fix. The bridge no longer starts a backend on its own.
- Sleep: on macOS the vault locks as soon as the system announces sleep or the session switches to another user, not only when the next check notices.
- Sync format 2 in the app and the CLI: the device's keys live inside the encrypted vault, manifests carry no content hashes, and no `age` binary is needed. Format 1 repositories are refused (`UNSUPPORTED_REPOSITORY`); start a new repository after upgrading.
- Packaging: `npm run dist:mac` and `npm run dist:linux` build the Rust programs and enforce size budgets; the release inventory lists the Rust crates. The packaged smoke test checks each tool starts in under 250 ms and the app stays under 250 MiB at start. Signing with a Developer ID identity and notarization run when their credentials are configured; public builds stay unsigned.
- Linux: no Chromium sandbox helper, `--harden` or launcher script any more; screen lock is read from logind.
- Removed: the Electron app, the Node backend and bridge, `cli.cjs` (including `import-legacy`: use 0.2 to import from the earlier fork, then upgrade), the Swift Keychain and clipboard helpers, and the Playwright UI test, replaced by `npm run test:desktop`.

## Changes to the 0.2 app after 0.2.0-preview.1 (never released; the 0.3 rewrite carries their behaviour forward where it applies)

- Rust core: `crates/vaultos-core` implements vault format v4, which the app does not use yet. It has Argon2id key derivation, an optional per-vault Secret Key, a Vault Key with one key per project, and item metadata and secrets sealed separately with XChaCha20-Poly1305. The whole file is authenticated, and a signed, hash-chained audit log is anchored in the vault. The store keeps `store.js`'s ownership, delegation, approval, history, Undo, stale-write and lock-file rules. Upgrading from v3 is explicit and one-way, and keeps a backup of the v3 file. CI runs rustfmt, clippy, the tests and cargo-deny on Linux and macOS; `fuzz/` has cargo-fuzz targets for the parsers.
- Desktop: a menu bar item (a tray icon on Linux, off by default there) shows whether the vault is locked, how many agent keys await approval and sync health, and opens Quick Access, the window, Lock, Settings and Quit.
- Desktop: Quick Access. ⇧⌘Space (Ctrl+Shift+Space on Linux) opens a floating search panel from any app: ⏎ copies the value, ⌘C the username, ⌘O opens the website, ⌘⏎ shows the key in VaultOS. It unlocks with the master password or Touch ID, never receives values, and uses its own IPC channels that only it can call. The shortcut can be changed or turned off in Settings.
- Desktop: search across every project (⌘K or View → Search), ranked by key, project, username, email, website and note.
- Desktop: closing the window locks the vault and, with the menu bar item on (the macOS default), leaves VaultOS in the menu bar instead of quitting. Quit from the menu bar item or with ⌘Q.
- Desktop: copies on macOS are marked concealed and transient, so clipboard managers that honour those markers skip them, and are kept off Universal Clipboard. The 30-second clear now leaves the clipboard alone if you copied something else in the meantime.
- Desktop: an application menu with Settings (⌘,), Lock (⌘L) and Search; reload and developer tools only in development builds.
- Desktop: opt-in Open at login (starts locked in the menu bar) and opt-in notifications for agent keys awaiting approval and keys expiring within 7 days. Notifications never name keys.
- Desktop: the password field in Add key hides the value until you choose Show.
- Dependencies: Electron 45.1.0, @modelcontextprotocol/sdk 1.32.2, dotenv 18.0.9, @electron/osx-sign 2.7.2, playwright 1.64.1 and @hono/node-server 2.1.6.
- Storage: history is capped at 1 MB as well as 2,000 entries, dropping the oldest first, so large values no longer grow the vault without limit. Revert still works for the entries kept.
- Sync: the vault copies a pull writes to `backups/` are pruned to the newest 20 plus any from the last 30 days. Other files in `backups/` are left alone.
- Keychain: an unlock with remembering on rewrites the stored password only when it is missing or different, instead of on every unlock.
- Desktop: the app is named VaultOS (VaultOS.app on macOS) instead of VaultOS Preview. The data directory, Keychain and Secret Service names, bundle identifier and Linux install paths keep their `VaultOS-Preview` and `org.vaultos.preview` names, so existing vaults and remembered passwords carry over.
- Desktop: a plain interface. The platform's own font, neutral greys with one blue accent, compact controls and hairline borders replace the mascot, the rounded display font, the cream-and-orange palette and the large pill buttons. No web fonts are bundled or loaded any more (about 124 KB less), and the renderer CSP now sets `font-src 'none'`.
- Sync: a pull decrypts only sync files it has not already read. Every pull used to run `age` once per record; repeating a pull of 200 unchanged records went from about 840 ms to 36 ms.
- Performance: an .env import saves the vault once instead of once per key (200 keys: about 1.8 s to 14 ms), **Approve all** approves every pending key in one confirmed save, password rotation derives each backup key once instead of twice per file, and a sync round asks Git for its branch and remote once.
- Desktop: overlapping unlocks (a Touch ID prompt and a typed password) no longer start a second API server or report that another process owns the vault, and Lock clears a copied value still on the clipboard.
- API: an agent that creates a project gets the project and its grant to it in one save, never one without the other.
- Performance: saving no longer repeats the vault's scrypt key derivation. Every edit, approval or deletion took about half a second and froze the desktop window while it ran; a write now takes a few milliseconds. The key for the vault's current salt is kept while unlocked and zeroed on lock; the file format is unchanged.
- Sync: fetch and push run asynchronously, so a slow remote no longer freezes the desktop window or the agent API during a sync round, and over SSH a round's fetch, push and verifying fetch share one connection (kept for five minutes) instead of handshaking three or four times. Your own `GIT_SSH_COMMAND`, `GIT_SSH` or `core.sshCommand` turns this off. Remote sync operations on one checkout now run one at a time.
- Dependencies: Electron 44.10.0 (GHSA-jr5w-w6x2-84p9) and patched transitive packages (body-parser, undici, zod, qs, hono, fast-uri, ip-address) clear the `npm audit` advisories that failed CI.
- Service and autosync: another process saving the vault (the CLI, or the desktop app while the service runs) no longer stops the always-on service or halts autosync. A save renames `vault.enc` into place and releases `write.lock` a moment later. A check that landed in between failed with "Another VaultOS process owns this vault": the service stopped serving ("could not reload the changed vault") and autosync halted with `ERROR`. Reload now waits for that save to finish, and an autosync round that meets it ends as `VAULT_BUSY`, which is retried and not halted, so a round never runs on the older copy in memory.
- Sync: one failed commit no longer stops a device syncing. The failed round left this device's manifest uncommitted under a heartbeat commit it never pushed, Git then refused every rebase onto the other device's commits ("cannot rebase: You have unstaged changes"), and each round halted as `GIT_HISTORY_DIVERGED` until the file was stashed by hand. Before it fetches, a round now commits files an earlier round wrote but did not commit (ciphertext, and this device's own manifest and heartbeat), provided the checkout still verifies. A failed commit unstages its paths, reports Git's own error instead of "Unrelated staged files" (which it also said when its own `git diff` failed), and is retried as `COMMIT_FAILED` instead of halting. A commit that fails three rounds in a row, on a stale `index.lock` for example, still halts with Git's reason. Uncommitted changes that block a rebase are reported as `LOCAL_SYNC_REPO_DIRTY`, not as diverged history. Conflicting records, signature, replay and unreadable-record errors still halt.
- Sync: an edit made on one device now reaches the other as an ordinary update. Pull compares each record with the last synced version (the sync index) and its revision, and only reports a conflict when both devices changed it. Previously any difference was a conflict, which halted autosync on the other device after every edit or approval.
- Sync: a file in a sync folder that sync did not write, such as the `.DS_Store` Finder leaves in a folder you open, no longer stops sync on every device. A push ran `git add` on whole folders, so such a file could be committed and pushed, and each device that pulled it then refused the repository as "Unsigned or modified ciphertext" and halted autosync. Already in the checkout before a round, it halted this device the same way, and the desktop called the device "Not sent". Sync now signs, reads, commits and deletes only files under the names it writes. A file that only this checkout has is ignored and not counted as unsent. A file with any other name that arrives in a commit in `records/`, `tombstones/` or `manifests/` is still refused, now as `Unexpected file in the sync repository`. A stray file Git already tracks (committed by hand or by an older version) is taken out of the repository by the next push, with the local copy left in place, so removing it with `git rm` or by hand and then pushing cleans it up.
- Sync: a manual pull in the desktop app, and `sync pull` / `sync accept-conflicts` in the CLI, now say why sync stopped (an unreachable remote, a diverged Git history, uncommitted changes in the sync checkout, records that could not be decrypted) instead of "File operation failed; check permissions and …". That generic line is now kept for Node's own file and system errors, which can name paths, in the CLI, the desktop app and the agent API alike.
- Sync: when verification stops a pull, autosync now records why. The error put each problem on its own line after `refusing to pull:`, and autosync keeps only an error's first line, so its status, `vault_status` and the `sync_halted` activity entry said `ERROR: refusing to pull:` and nothing else. The problems are now on that line (`refusing to pull: Unsigned or modified ciphertext`), and the halt's state is `SIGNATURE_INVALID`, the name `sync status` already used for it. A push that fails the same checks reports the same state, and so does a round that finds files an earlier round left uncommitted and they fail verification.
- Sync: a file that only this checkout has no longer stops a push wherever it is, so a `.DS_Store` Finder writes when you open the sync repository folder itself, or an editor's swap file, no longer halts autosync with "Sync repository contains unrelated changes". Sync leaves such a file alone: it is never committed or deleted. A change to a file Git tracks or has staged outside sync's folders still stops a push, and the error now names the file. So does a `.gitignore`, `.gitattributes` or `.gitmodules` anywhere in the checkout, including inside sync's folders: a `.gitignore` in `records/` kept new records out of the commit that this device's manifest signed, so the push reported success and every peer then refused to pull ("Signed ciphertext is missing"). A push also stops, naming the file, when an ignore rule outside the checkout (`.git/info/exclude`, a global excludes file) hides a file sync wrote: before, the push reported success with a manifest that signed a record it never committed, and every peer then refused to pull ("Signed ciphertext is missing").
- Sync: the desktop app finds `age` and `age-keygen` when they are not on its PATH. Opened from the Dock or Finder on macOS, the app gets launchd's PATH (`/usr/bin:/bin:/usr/sbin:/sbin`), so `age` installed with Homebrew or into `~/.local/bin` was invisible: its first sync failed with "age is not installed" and autosync halted for good, while the same vault synced from a terminal or the background service. A tool missing from PATH is now also looked for in `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin` and `/home/linuxbrew/.linuxbrew/bin`.
- Sync: when autosync halts, the reason is written to the vault's activity log (`sync_halted`, by `autosync`), and the desktop app also prints autosync messages to its console. Before, the desktop discarded them, so a halt left nothing saying why.

## 0.2.0-preview.1

- `node cli.cjs import-legacy --from DIR [--plan]`: an explicit, one-time import of a data directory from the earlier vault-os fork into a new, empty preview data directory. It validates every record first, never modifies the source or copies its plaintext password file, keeps agent token hashes with deny-by-default access (or `--grant-all-existing-agents`), holds previously denied keys for approval, and maps a matching shared agent token to `agents/NAME.token`.

- Optional always-on backend: `backend.cjs --service` waits while the desktop owns the vault, takes over when it closes, retries Keychain unlock, restores a removed session file and reloads a vault replaced on disk. `scripts/install-service-macos.sh` installs it as a LaunchAgent on request. It requires background access and exits when that is off.
- Optional autosync (off by default) in whichever process owns the vault, with `POST /sync` / `node cli.cjs sync now` for owner-requested rounds and sync health in `vault_status`. It halts on conflicts and verification errors instead of resolving them.
- Optional soft lock policy (default remains hard): screen lock, sleep and idle lock only the window while agents keep working; the Lock button stays a full lock.
- Optional Touch ID on macOS (all off by default, requires background access): unlock the window with Touch ID, ask for it when the window opens, and confirm human-only actions with a 30-second grace window. The main process enforces confirmations and falls back to the master password when Touch ID is unavailable or cancelled; Lock resets the grace window and still requires the typed password.

- Linux (source-built preview): optional password remembering through the Secret Service (`secret-tool`) with no plaintext fallback, `npm run dist:linux` packaging, a per-user installer with run-time Chromium sandbox detection, and an opt-in systemd user unit for the headless backend.
- Agents: optional, default-off all-access grants (`allProjects`, `anyRoot`), set only by a human in Settings → Agents or the admin CLI.
- `vaultos-agent` shell client (`agent-cli.cjs`) for enrolled agents, with the bridge's grants and token discovery (`VAULTOS_AGENT_TOKEN`, a private `VAULTOS_AGENT_TOKEN_FILE`, or `VAULTOS_AGENT` with `<data dir>/agents/NAME.token`).
- Admin CLI commands for agents, pending approvals, the approval relay and headless password rotation, all authorized by the master password.
- Optional approval relay route (`POST /pending/decide`) authenticated by a separately configured secret; an **Approve all** button in the pending banner.
- MCP bridge: distinct locked/not-running errors, deduplicated backend start through an installed service or a one-shot `backend.cjs`, sync health and bridge hash in `vault_status`, and `import_env` `createProject`.

- Sync: a pull no longer marks unpushed local records as already published. A local edit kept by `sync accept-conflicts` stayed on that device: the next push skipped it and `sync status` reported nothing outgoing. The push index now matches what the sync repository holds, and an index affected by the old behavior is repaired by the next pull.
- Sync: conflicting versions with the same revision and timestamp now resolve by content hash, so every device keeps the same version instead of each keeping its own.

## 0.1.0-preview.1

First standalone public macOS preview.

- Local encrypted project vault, desktop editor, expiry metadata, guarded history undo, encrypted PDF export and recovery CLI.
- MCP bridge with separate agent identities, project/folder grants, ownership rules, injection quarantine and explicit reveal scope.
- Real desktop/API lock, sleep and idle lock, optional native Keychain storage without plaintext fallback, restricted renderer and hardened packaging fuses.
- Atomic persistence with stale-writer protection; bounded, safely quoted file exports and symlink checks.
- Optional age/Git sync with pinned peer trust, approved recipients, signed ciphertext verification, replay checks, backups and explicit conflict acceptance.
- Standalone history, synthetic test fixtures, dependency lockfile, contributor/security documentation, and unsigned macOS release automation.

This is an evaluation prerelease, without Developer ID signing, notarization or an independent security audit. See release notes for executed platform verification.
